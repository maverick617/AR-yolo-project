# 三侧面 Tag + 一杯底 Tag 杯子 Demo：设备测试与排错

## 测试前检查

- 使用 `Assets/Scenes/SampleScene.unity`，并执行一次 `Tools > AR 80s Retro > Configure Build Scene (4-Tag Cup)`。
- 使用 `tagStandard41h12` 的 ID 0、1、2、3。每个 Tag 的有效黑色方形边长都是 1 cm，场景值为 `tagSizeMeters = 0.01`；白边不计入尺寸。
- 俯视且把手朝 3 点：ID 0 位于把手正对面的 9 点，ID 1 在 1 点，ID 2 在 5 点。三者的上边均朝杯口、正面均朝外、中心均处于杯身高度中点。
- ID 3 平贴杯底且正面朝外；杯子正放时标签朝下，图案上边指向把手。
- ID 1 和 ID 2 不可交换。位置或图片朝向错误会直接变成虚拟把手的角度误差。
- 1 cm Tag 建议先在约 15–30 cm 距离测试，并保证清晰、平整、无反光。
- 使用竖屏；当前相机帧和 Tag 姿态补偿按 Portrait 配置。
- 首次尺寸稳定时手机和杯子保持静止即可，不要绕杯移动手机。

## 屏幕状态

### `WAITING: show cup + AprilTag 0/1/2/3`

尚未同时得到有效 `cup` 检测和任一已配置 Tag。控制台应能看到 `YOLO detect: cup`。

### `CUP FOUND - WAITING FOR APRILTAG 0/1/2/3`

YOLO 已找到杯子，但 ID 0、1、2、3 都没有新鲜位姿。检查：

- Tag family 是否为 `tagStandard41h12`；
- 是否打印了 ID 0/1/2/3 之外的标签；
- 黑色有效方形是否确实为 1 cm；
- 标签是否完整入镜、清晰、平整且没有被手遮挡；
- 真机是否安装了重新构建后的最新版 App。

### `AUTO SIZING CUP: n/5 - HOLD STILL`

程序正在同一个普通观察角度收集 5 个尺寸测量帧并取中值。保持当前画面约 1–2 秒即可；不需要移动手机，也不需要绕杯扫描。若进度不增加，通常是 YOLO、Tag 或深度/透视测量中有一项暂时无效。

### `SHOW SIDE APRILTAG 0/1/2 TO SIZE CUP`

首次定尺寸时只看到了杯底 ID 3。底视图不能可靠给出杯高，请先让任一侧面 Tag 与完整杯框保持可见约 1–2 秒；尺寸锁定后 ID 3 可以正常接管翻转跟踪。

### `TRACKING CUP (APRILTAG n)`

模型已建立。`n` 是当前用于跟踪的 Tag。杯子转动时程序优先保持当前 Tag，当前 Tag 消失后才切到最新可见的另一个 Tag，避免多个 Tag 同时可见时来回抖动。切换不会创建第二个模型。

### `APRILTAG HIDDEN - SHORT POSITION FALLBACK`

所有 Tag 暂时不可见。YOLO 和尺寸估计仍有效时，系统最多约 0.8 秒修正位置并保持最后旋转；重新露出任一 Tag 后恢复完整 6DoF。

### `CUP LOST - SHOW CUP + APRILTAG 0/1/2/3`

杯子和四个 Tag 都超过丢失宽限时间。让杯子与任一 Tag 回到画面即可。

## 180° 旋转验收

1. 让 ID 0 朝向相机，等待进入 `TRACKING`。
2. 记住现实把手在屏幕中的一侧，确认虚拟把手在同一侧。
3. 缓慢将杯子绕竖轴旋转，状态应从 ID 0 交接到 ID 1 或 ID 2。
4. 继续转到 180°。模型应持续移动/旋转且只有一个实例；现实把手换到另一侧时，虚拟把手也应同步换侧。
5. 再把杯子翻转到底部朝向相机，状态应交接到 ID 3，模型杯底也应朝向相机且把手方位保持一致。
6. 再倾斜并拿起杯子，确认位置、俯仰和滚转均跟随。

若绕竖轴旋转到某一角度三个侧面 Tag 都检测不到，先缩短拍摄距离、改善光照和打印质量。三个 1 cm Tag 在最差角度仍可能约 60° 斜视，因此实际识别距离不能按大标签的距离预期。杯底 ID 3 主要覆盖翻转，不代替侧面一圈的可见性。

## 模型位置或方向不对

1. 若虚拟把手总是相差固定角度，先核对俯视钟表位置和 ID，尤其不能交换 ID 1/2。
2. 确认侧面 ID 0/1/2 的图案上边朝杯口，杯底 ID 3 的图案上边指向把手。贴反或原地旋转都会造成错误的三维姿态。
3. 三个侧面 Tag 应在同一高度带并尽量位于杯身高度中点；高度误差会成为模型中心的上下偏移。
4. Tag 正面应沿半径朝外。歪贴会使模型跟随时带有固定倾斜。
5. 使用平面卡座时，将标签平面到杯面的真实间隙填入 `tagMountStandoffMeters`。
6. 若新模型仍约大 5 倍，先确认已重新运行四 Tag 场景配置并清除旧注册数据。新路径会以 YOLO 投影高度二次校正，不应再把 `tagSizeMeters` 当成杯子宽高；场景中的 `0.01` 仍要正确，因为它影响 Tag 的三维距离与平移跟踪。
7. 从旧版本升级后，重新运行场景配置菜单、保存场景并重装真机 App；必要时执行一次 `Clear Saved Cup Registrations`。
8. 若 ID 0/1/2 都让模型固定横躺约 90°，检查 `KeijiroAprilTagFrameDetector`：`compensateFrameRotation` 必须关闭，`detectorToCameraRotationCorrectionEuler` 必须为 `(0,0,0)`。相机纹理已经是竖屏，不能再次旋转 Tag 位姿。
9. 若模型杯身明显小于 YOLO 杯框，确认 `RetroReplacementManager` 的 `yoloScreenHeightFill = 0.96`。最终缩放只匹配 YOLO 高度，不会因为复古把手比现实杯更宽而把整个模型缩小。

默认规则的最终 Tag→杯子旋转为 ID 0 `(0,-90,0)`、ID 1 `(0,+150,0)`、ID 2 `(0,+30,0)`、杯底 ID 3 `(0,+90,+90)`。四个标签的局部杯心方向都是 `(0,0,+1)`。只有实体位置和图案上边严格按本说明放置时才应使用这些值。

侧面标签的图片上边须朝杯口。杯底标签的法线只能确定杯轴，不能确定把手绕杯轴的角度，所以 ID 3 图片上边须指向把手；旋转粘贴会造成同角度的虚拟把手误差。所有 Tag 都不可见时只能短时更新位置并保持最后旋转；仅靠 YOLO 二维框和手机自身 IMU，无法恢复人手任意改变的杯子角度。

## 模型与渲染限制

当前 cup FBX 是连续网格，系统优先匹配杯身直径、高度、中心和把手方向，无法独立拟合不同现实把手的孔径与伸出长度。产品级适配应使用独立 `Body`、`Handle` 和明确 Pivot 的参数化 Unity Prefab。

检测版 YOLO 不会擦除现实杯子的像素。分割模型能改善测量与边缘遮罩，但完全隐藏现实杯仍需要背景补全。测量用 `AROcclusionManager` 应位于 `AR80sRetro System`，不要挂回 AR Camera，否则现实杯的深度可能遮住同位置的复古模型。
